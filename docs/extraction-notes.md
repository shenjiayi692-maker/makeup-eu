# 提取方法与处理过的疑难情况

## 为什么不用 OCR，也不靠 x 坐标猜列

这份 PDF 有完整文字层，而且**表格边框是真实的矢量线**（pdfplumber 的 `curves`）。
所以直接从边框还原单元格网格：

- 竖线给出列边界。每个附件内部所有页完全一致（附件 III 的 9 列在 243 页上完全一致），
  但**附件之间不一致**，所以边界是逐页从边框推出来的，不是写死的。
- 横线给出行边界。**横线覆盖到 a 列 = 新条目开始**；只覆盖部分列的横线 = 条目内部的
  子行（多物质或分档）。
- 每个字符按几何位置落进单元格，再按基线重组成行。

## 逐条对应最初提的需求

| 需求 | 处理方式 |
|---|---|
| 条目跨页合并 | 某页第一个行块若 a 列为空 → 并入上一条目；`pages` 列记录跨了哪几页 |
| f/g 的 (a)(b)(c) 分档 | 见下，四种依据 |
| c/d/e 多物质拆行 | 见下 |
| g 列是文字或为空 | 原文保留在 `max_concentration`，`max_conc_value` 为 NULL |
| ▼Mnn 修订标记 | `amended_by`；连续行的标记叠加（`▼M36 ▼C6`），相隔较远的取最后一组 |

## 分档：四种依据（`conditions.tier_source`）

按可靠性从高到低尝试：

1. **`label`** — 原文有显式标签。**每一列各自按自己的标签切分**，再按字母对齐。
   这点很关键：同一档的 `(b)` 在 f 列和 g 列常常不在同一条基线上（附件 V/56 最明显），
   按 y 横切会错位。
   - 一列中第一个标签之前的文字，或整列都没标签，视为**对全部档次生效**，
     复制进每一档，让每行自成一体。例：V/53 的 g 列只有一个 `0,1 %`，(a)(b) 都拿到；
     V/61 的 `(a) and (b) 1 %` 同理；VI/4 的 `For a) and b) …` 前缀进入全部三档。
   - **附件 VI 写成 `a)` 没有前括号**，其余附件写成 `(a)`，两种都认。
   - 标签后必须跟空格或行尾，否则 `benzo(a)pyrene` 折行后的 `(a)pyrene` 会被当成标签
     （附件 IV/126 踩过）。
   - 只接受从 a 开始连续的字母。附件 III/2a 的 `(i) 8 % (ii) 11 %` 是罗马数字小项，
     不是第 9 档——因为该条目没有 e–h 档，`i` 被判定为非标签。
2. **`rule`** — 条目内有横线把 f/g 切开。这种横线同时穿过 h/i，所以 h/i 一起切（V/3）。
3. **`aligned`** — 无标签，但 g 列每个限值行与 f 列产品类型逐行对齐，
   且**每一档都确实分到了 f 列文字**才切（V/1 三档、V/35 两档）。条件卡得严，
   是为了不把 V/39 那种"一个限值折了 7 行"的散文切碎。
4. **`none`** — 单一档次。

**h/i 只在 `label` 和 `rule` 下切分**；`aligned` 只切 f 和 g，h/i 保留条目级完整文本，
否则会把 V/12a 的警示语从 "designed for application on the / nappy area" 中间劈开。

## 多物质拆分：拆不齐就不硬拆

- c 列含逗号 → 按逗号切，但**忽略后面跟数字的逗号**，保护 `2,4,4-trimethylpentyl` 这类位次。
- c 列不含逗号（换行式列表）→ 按 **d/e 列有内容的基线**做锚点分组：
  名字折行时第二行没有对应的 CAS/EC，会并回上一个物质（V/12a 的
  `potassium` + `propylparaben` 正确合成一条）。
- **附件 II 例外**：它的 b 列是单个化学名而不是物质列表，名字里的逗号是名字的一部分
  （`N,N-Dimethylaniline`、`Colchicine, its salts and derivatives`），所以整格当一个名字。
  这个区别由 `spec.py` 的 `name_list` 控制。
- CAS/EC 用模式匹配抽取（`\d{2,7}-\d{2}-\d` / `\d{3}-\d{3}-\d`），容忍编号被折行拆开
  （V/3 的 `59866- 70-5` 能还原）、容忍 `/` 或逗号分隔（VI/27 的三个 CAS）。
  EC 列中间的 `—` 保留为位置占位（IV/149）。
- **三列数量对不上时不做任何配对**：整条压成一行，三列各自保留完整列表，
  标 `split_ok=0` 等人工处理。这是刻意的——附件 IV/150 的 c 列
  `Aluminum stearate / Zinc stearate / …` 换行了但 d/e 不对齐，硬拆会**把物质和 CAS 配错**，
  在合规数据里配错比不配更糟。
- 一个名字配多个登记号（如 IV/149 Anthocyanins 的 5 个 CAS）是明确的，不算歧义，不标记。

## 其他处理掉的坑

- **上下标**：按字号识别（正文 8.4pt，上下标约 5.5pt）并归回原行，`SO₂` 不再变成两行。
- **断字连字符**：软连字符 `\xad` 结尾的行与下一行直接接合（`concen-tration` → `concentration`）。
- **重复画的边框**：附件 VI 有些行的边框画了两次、相差 0.4pt，会产生两个内容相同的行块。
  现在把 1.5pt 内的横线合并。
- **末页空白块**：表格结束后的空白区域会被识别成行块，直接丢弃，不是"已删除条目"。
- **表格下方的脚注**：用列竖线的纵向延伸判断表格真正结束在哪，脚注区不会被当成表格内容。
- **脚注跨页**：附件 III 的脚注溢出到 383、384 两个整页（这两页没有表格，
  会被报告为"未按表格解析"，是正常的）。所以脚注是扫描附件全部页面的表格下方区域，
  不是只看最后一页。
- **脚注区不用几何聚类**：`_____` 删除线横跨两条基线，几何聚类会把脚注编号认到隔壁行去。
  这一块改用 PDF 文字引擎自己的行组装（pymupdf），再用 `rotation_matrix` 把坐标
  映射回网格空间。附件 II 的脚注写成 `( 1 )`，括号内有空格，也一并认。
- **页边的竖排页码**：`02009R1223 — EN — …` 竖排印在页边，字符会落进脚注区。
  用 `upright` 属性排除。
- **编号单元格里的修订标记**：附件 III 有 `►C14 386 ◄` 这种把标记写进编号格的，
  已从 `ref_no` 剥离并记进 `mid_amendments`。
